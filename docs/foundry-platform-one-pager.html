CI/CD decision guide

Evaluation approaches

Choose the lightest option that answers the release question. Most production pipelines combine deterministic tests, a repeatable pre-production evaluation, and post-production trace monitoring.

Approach Pros Cons Best use
Deterministic tests Fast, inexpensive, stable, and clear for schemas, tool arguments, and policy rules. Cannot judge nuanced language quality or end-to-end task completion. Every commit and pull request.
Local or offline SDK evaluation Early feedback, easy debugging, and support for scoring precomputed responses. Local identity, tools, networking, and configuration can differ from deployment. Developer loop and lightweight PR evaluation.
Foundry cloud SDK evaluation Fine-grained control over datasets, evaluators, mappings, thresholds, evidence, and target versions. Requires orchestration code, polling, SDK maintenance, Azure access, time, and model cost. Authoritative release gates with custom policy.
azd ai eval Reviewable YAML configuration, natural azd lifecycle integration, and built-in failure thresholds. Preview command surface, less custom reporting, and nonzero exits can represent different failure types. Config-as-code pipelines with less custom SDK orchestration.
Microsoft evaluation GitHub Action Minimal workflow code, GitHub summaries, confidence intervals, and candidate comparison. Preview and GitHub-specific, with less flexibility than a custom SDK gate. Rapid GitHub Actions integration and version comparison.
Trace or continuous evaluation Uses real interactions and identifies changing data, tools, user behavior, and upstream drift. Post-release signal with privacy, sampling, and reproducibility considerations. Production monitoring and discovery of new regression cases.
Cloud evaluation SDK azd evaluation CLI Evaluation GitHub Action AI red teaming Evaluation and observability concepts
